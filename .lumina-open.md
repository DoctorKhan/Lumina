# App Discovery Ranking and Quality Rules

This document defines how apps are filtered and ranked for public discovery surfaces.

It is intended to answer:

- Which apps are eligible to appear publicly.
- How trending scores are computed.
- How metadata quality (image + description) affects rank.
- Why some apps are hidden even if they exist in the database.

---

## 1) Public Discovery Eligibility (Hard Filters)

Before ranking is applied, an app must pass public eligibility checks.

An app is eligible for public discovery only if all of the following are true:

1. `isArchived = false`
2. `moderationStatus = ACTIVE`
3. `discoveryTier ∈ {LIMITED, FULL}`
4. `latestReleaseId != null` (prevents placeholder or unreleased rows)
5. `imageUrl != null` (must have an icon)
6. `description` exists and is not empty
7. `description.length >= 40` (after trim)

This applies to:

- Home page public app queries
- Public `GET /api/apps` listing routes

Creator-scoped views remain less strict so developers can still see and fix incomplete apps.

## 2) Trending Score Formula

The trending score is a weighted sum of recency, activity, engagement, reviews, status, verification, and metadata quality.

Let:

- `A_c` = app age in days since `createdAt`
- `A_a` = activity age in days since `lastActivityAt` (fallback to `updatedAt`/`createdAt`)
- `P` = `playCount`
- `V` = `viewCount`
- `R` = `reviewCount`
- `Q` = `averageRating` (0 if null)
- `I` = indicator for icon presence (`1` if image exists, else `0`)
- `D` = trimmed description length

### 2.1 Subscores

Freshness:

\[
S_{fresh} = \frac{32}{1 + A_c / 7}
\]

Recent activity:

\[
S_{activity} = \frac{18}{1 + A_a / 3}
\]

Engagement (log-scaled):

\[
S_{engagement} = 9 \cdot \ln(1 + \max(P,0)) + 4 \cdot \ln(1 + \max(V,0))
\]

Review impact:

\[
S_{reviews} =
\begin{cases}
2R + Q \cdot \min(R,5), & R > 0 \\
0, & R = 0
\end{cases}
\]

Quality bonus from sufficiently reviewed rating (`TOP_RATED_MIN_REVIEWS = 3`):

\[
S_{quality} =
\begin{cases}
3Q, & R \ge 3 \\
0, & R < 3
\end{cases}
\]

Status bonus:

\[
S_{status} =
\begin{cases}
6, & status = live \\
2, & status = raising \\
0, & otherwise
\end{cases}
\]

Verification bonus:

\[
S_{verified} =
\begin{cases}
4, & isVerified = true \\
0, & isVerified = false
\end{cases}
\]

Image bonus / penalty:

\[
S_{image} =
\begin{cases}
6, & I = 1 \\
-10, & I = 0
\end{cases}
\]

Description bonus / penalty:

\[
S_{desc} =
\begin{cases}
5, & D \ge 100 \\
2, & 40 \le D < 100 \\
-8, & D < 40
\end{cases}
\]

### 2.2 Final Trending Score

\[
S_{trending} =
S_{fresh} +
S_{activity} +
S_{engagement} +
S_{reviews} +
S_{quality} +
S_{status} +
S_{verified} +
S_{image} +
S_{desc}
\]

Apps are sorted by `S_trending` descending.

Tie-breakers:

1. Higher `averageRating`
2. Newer `createdAt`

---

## 3) Top Rated Row (Separate from Trending)

Top Rated is computed independently from trending.

Eligibility:

- `reviewCount >= 3`
- `averageRating > 0`

Weighted rating used for sorting:

\[
W = \frac{Q \cdot R + 3.5 \cdot 3}{R + 3}
\]

This shrinks low-sample apps toward a prior mean of `3.5`, reducing volatility from small review counts.

Top Rated sorting order:

1. Higher `W`
2. Higher `reviewCount`
3. Newer `createdAt`

---

## 4) Why Broken Apps Are Less Visible (or Hidden)

Apps are prevented from public discovery if they fail hard quality gates such as:

- No release (`latestReleaseId` missing)
- No icon (`imageUrl` missing)
- No meaningful description (`description` too short)

Even among eligible apps, metadata quality affects rank:

- Missing icon receives a negative score contribution (`-10`)
- Thin descriptions receive a penalty (`-8`)
- Complete metadata receives positive boosts (`+6` image, `+2` to `+5` description)

Net effect: incomplete apps are suppressed; high-quality listings rise.

---

## 5) Worked Example (Metadata Quality Impact)

Assume two apps with identical recency, activity, engagement, and review stats.

- App A: has icon + 120-char description
  - `S_image = +6`
  - `S_desc = +5`
  - metadata subtotal = `+11`

- App B: no icon + 20-char description
  - `S_image = -10`
  - `S_desc = -8`
  - metadata subtotal = `-18`

Relative advantage:

\[
11 - (-18) = 29
\]

So App A gets a +29 point edge in trending score from metadata quality alone.

---

## 6) Operational Notes

- The home page and public apps API both use strict discovery filtering.
- Internal creator/admin flows intentionally remain more permissive for iteration and remediation.
- Any future quality signals (health-check pass/fail, runtime playability probes) should be added as:
  1) hard eligibility constraints, and/or
  2) additional weighted score terms.
